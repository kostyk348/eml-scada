## [1.0.0] — 2026-10-21

Первый релиз: v0.1 доведён до состояния, в котором его можно ставить и проверять.

### Добавлено

- **JSON-API**: `/healthz`, `/api/state`, `/api/alarms`, `/api/series`,
  `/api/history`, `/api/verify`, `POST /api/ack`, `POST /api/setpoint`.
- **Конфиг** `config.json` с глубоким merge и валидацией на старте
  (`ConfigError` вместо тихо неверного поведения); `--config` и
  `--store`-локальный файл, `<store>/config.json` создаётся при первом запуске.
- **Целостность** (`scada/integrity.py`): независимый Python-парсер контейнера
  (границы секций, непрерывность дельт, инварианты трейлера) + append-only
  журнал якорей `store/anchor.eml` с цепочкой `prev`/`self`.
- **Ретенция** (`scada/retention.py`): `keep_hours`/`max_records` для историка,
  TTL для `.done` и осиротевших `.tmp` в спуле шины.
- **Ротация станции** по числу дельт в `store/archive/`, с якорем на финальное
  имя архивного файла.
- **Живой график** из кольцевого буфера в памяти (1 час при 1 Гц); tagdb
  читается только для глубокой истории.
- **Восстановление состояния** из контейнера станции после рестарта.
- **CLI**: подкоманды `run`, `headless`, `verify`, `demo`; старый синтаксис
  `--headless --seconds N` сохранён.
- **Демо** `python -m scada.run demo`: два типа подмены (тело дельты и
  согласованная перезапись последней дельты).
- **Тесты**: 45 (unit: алармы, конфиг, ретенция; integration: шина, движок,
  целостность), маркер `integration` для тестов, которым нужен `emlbox`.
- **Упаковка**: `pyproject.toml`, `eml-scada` console script, CI-workflow.
- **Документация**: README с замерами, API, конфигом и честными границами.

### Изменено

- Состояние станции пишется **пачкой** раз в `station.state_persist_s` вместо
  `kv set` на каждую точку каждого тика: 5.3 → 0.2 дельты/с.
- Шина: один адрес — один потребитель (движок больше не читает чужую почту).
- Публикация сообщения атомарна (`tmp` + `os.replace`).
- `verify` по умолчанию глубокий: структура + `emlbox verify` + якорь.
- `emlbox` ищется по `EMLBOX` → `target/release/emlbox.exe` → `PATH`, а на
  старте проверяется `check_binary()` (падать сразу, а не на первом сообщении).

### Исправлено

- Гонка «список — чтение» в спуле: файл, съеденный другим потребителем,
  пропускается, а не роняет цикл.
- Частично записанные сообщения больше не видны читателю.
- `setpoint_ack` учитывается в статистике (раньше ACK мог потеряться).
- Self-hash якоря ложно не сходился примерно в трети случаев: `ts` был
  float, а JSON-round-trip через контейнер теряет последний бит
  (`…7396681` → `…739668`). Время в журнале теперь целые миллисекунды.
- `emlbox` вызывался без `stdin=DEVNULL`: при невалидном унаследованном stdin
  (служба, CI, некоторые оболочки) каждый вызов падал с `WinError 6`.
- BADQ-дефект применялся ко всем контроллерам, а не только к `sim.fault_cid`,
  и забивал лог алармов шумом.
- `config.json`, сохранённый с BOM (Блокнот, PowerShell), не читался:
  теперь читается как `utf-8-sig`.

### Известные ограничения

- `emlbox verify` (mime-os) не хэширует tail index и трейлер — перезапись
  последней дельты с пересчётом хэшей им не ловится; ловится якорем.
- Якорь хранится на той же машине; офсайт-копия — только вручную
  (`export_head()`).
- Шина — локальный каталог: без сети, аутентификации и fan-out.
- Контроллеры — симуляторы; Modbus/OPC UA нет.
- У HMI нет аутентификации (слушает `127.0.0.1`).
- Файла `LICENSE` в репозитории нет, хотя в `pyproject.toml` указано
  `Apache-2.0`.
